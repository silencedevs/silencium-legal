1. Operator and scope

Silencium is a Discord bot associated with the Silence project. This policy covers the bot’s account and file-processing functions, and this static legal website. The association with Silence does not by itself identify the party responsible for processing personal data.

2. Information processed

The following describes the reviewed bot implementation. Actual hosting and operational practices still need confirmation.

  • Account identifiers: your Discord user ID and a Discord account name, or a name entered by the operator. An account can be added manually by the operator or created through bot use.
  • Settings and access: saved build configuration, token balance, per-file token cost, access status, daily build limit, input-size limit, account creation time, and internal record versions.
  • Build and credit history: interaction/request IDs, account links, timestamps, UTC usage-day values, input and output byte counts, reserved/delivered/refunded status, token adjustments and reasons, and administrative request identifiers and fingerprints.
  • Files: the submitted filename, attachment URL and size, file contents needed for compilation, and the generated output. These are processed separately from the account database as described below.
  • Discord context: Discord can include guild/server IDs, channel IDs, user/member details and permissions in an interaction. The bot handles this context to respond. The reviewed account database does not have fields for guild or channel IDs. An optional server ID may be configured by the operator for command registration.

The bot responds to slash commands; the reviewed implementation does not enable Discord’s Message Content intent or scan ordinary channel conversations. It contains no advertising, analytics or AI-service integration. This does not describe processing independently performed by Discord.

This website has no scripts, forms, analytics, external fonts, cookies or browser-storage features in its supplied code. GitHub’s hosting infrastructure can process technical request data; see section 5.

3. Why it is processed

Identifiers associate commands, settings and usage tokens with the correct account. Configuration determines how files are compiled. Usage records enforce access and size limits, reserve or refund tokens, prevent duplicate charges, and let the operator review interrupted builds and account changes. Files are processed to generate and return the requested output.

You need a Discord user ID for an account and file contents for a build. Without that information, those functions cannot be provided. You do not need to submit a file merely to read these legal documents.

4. Storage, retention and deletion

Account records

Account, configuration, build-metadata and credit-history records are stored in an operator-controlled SQLite database. Submitted source, generated artifacts, attachment URLs and credentials are not stored in that database. Showing only recent records in the admin interface does not delete older records.

The current code has no automatic expiry for account, build or credit records, and no self-service account-deletion command. Resetting /config resets build settings; it does not delete your account or history. Removing the bot from a server does not automatically erase those records.

Source and output files

Attachments are downloaded from Discord. File contents and output are handled in memory, and compilation uses a private temporary directory. That directory is normally removed when compilation finishes or fails. A hard crash, operating-system storage, swap or backups may leave copies; cleanup is not guaranteed secure erasure.

Generated files are returned through private Discord interaction replies. “Private” describes the reply’s visibility, not a guarantee about Discord’s storage, retention or deletion. Original uploads and returned attachments remain subject to Discord’s systems and policies.

6. Security measures

The reviewed implementation uses restricted local database/file permissions, parameterized database queries, bounded downloads and compilation, and an administration server bound to the local machine with origin and request-token checks. Bot replies are private. Application messages do not include source contents; SDK warnings are reduced to fixed messages without formatting request payloads or credential-bearing URLs.

These controls do not guarantee confidentiality, perfect security or secure erasure. The reviewed SQLite database is not application-encrypted at rest. Deployment access, disk encryption, backups and infrastructure logging need separate verification. Do not submit credentials or personal information that is unnecessary for your build.

7. Your rights, including in the EU

Where applicable law provides these rights, you may request access, correction, erasure, restriction or portability, and object to certain processing. If processing relies on consent, you may withdraw it without affecting earlier lawful processing. Rights depend on the circumstances and applicable exceptions.

If GDPR applies, you may complain to a competent data protection supervisory authority, including one in your habitual residence, workplace or the place of an alleged infringement. See the GDPR text.

Use the contact in section 1 to make a request. Provide your Discord user ID to help locate your records; do not send passwords or bot credentials. The operator must establish a proportionate verification and response process.
